# Repo Reaper

## Problem Statement

如何協助被 AI 代理產物拖累的開發者，以「核心目標」和「提出者」審問每個項目，刪除不需要的項目並維持精簡，同時不造成無法復原的損失？

## Recommended Direction

建立一個 skill `repo-reaper`，包含三個模式：

- **瘦身：** 確認核心目標，盤點項目，審問目標和提出者，提出表格，核准後刪除，最後把核心目標和檔案地圖寫進現有 README。
- **規劃審視：** 在實作前審視規劃項目，移除過度設計。
- **定期回顧：** 以 `git log` 比對基準提交，只審問新增項目。

瘦身結束時，skill 提議在專案規則中寫入 3 到 5 行維持規則，內容是「一進一出」和「規劃後執行審視」。

Claude Code 和 Codex 共用一份 `SKILL.md`。第一版從單一 skill 開始。單一 `description` 降低觸發準確度，或 `SKILL.md` 在移出細節後仍難以精簡時，再升級成包含多個 skill 的 plugin。

## 判斷規則

**核心目標**

- 瘦身：使用者確認核心目標之前，skill 不產出刪除提案。使用者不知道目標時，skill 以訪談協助找出目標。
- 規劃審視：使用者自己寫的任務要求視為已確認的目標。skill 在結果第一行引述原文。找不到原始要求時，skill 停下來詢問。

**判斷軸依項目類型區分**

- 規則、流程、防呆：必須有提出者。沒有提出者就列為刪除候選。
- 文件、程式檔案：依是否服務核心目標，或是否為運作所需來判斷。
- 規劃項目：審問「移除這個項目後，使用者要求的結果是否仍能達成」。達成要求所需的步驟，提出者是要求該結果的使用者。超出必要的項目需要獨立提出者。

**提出者**

| 提出者 | 需要的證據 | 仍要回答的問題 |
| --- | --- | --- |
| 具名的人 | 姓名和出處，例如 issue、PR、提交 | 這項要求是否仍適用？ |
| 真實事故 | 指得出的事件記錄 | 這個風險現在是否還存在？ |
| 無 | 只有「團隊」「最佳實踐」「AI 代理建議」 | 預設列為刪除候選 |

- AI 代理不算提出者。
- 有提出者不代表自動保留。
- Git 作者不等於提出者。來源提交只是線索，提出者由使用者確認。
- 追不到提出者時，目前維護者可在核准時認領。

**引用數**

- 文字檔：「其他文件引用它」不是保留理由。
- 程式檔案：以「是否可從入口點到達」判斷，刪除後必須通過建置和測試。

**硬規則**

- 既有項目只能在已提交且受 Git 追蹤時刪除。未提交變更、未追蹤檔案和被 `.gitignore` 忽略的檔案一律不動。規劃項目尚未產生，不受這條規則限制。
- 所有寫入都要先經使用者核准。skill 預設不 commit。
- 專案可以另外指定保護清單。

## Key Assumptions to Validate

- [ ] 一句核心目標足以支撐判斷：在一個曾經人工瘦身的專案上，以瘦身前的提交做回歸測試。
- [ ] 提出者大多能追到，或使用者能很快裁定：測試時統計「無」的比例和核准耗時。
- [ ] 同一份 `SKILL.md` 在兩個平台的行為一致：兩邊實際觸發並比較結果。
- [ ] 維持規則能讓使用者在規劃後實際執行審視：在真實規劃情境中測試。

## 成功標準

- **理解成本：** 使用者能看懂留下物件的用途，也知道東西要去哪裡找。AI 代理不再讀到互相矛盾的規則。
- **誤刪率：** 無法復原的損失必須為 0。可由 Git 復原的加回率約 10% 視為健康訊號。
- **精簡幅度：** 常駐載入量明顯下降。

## MVP Scope

- **包含：** 三個模式、內建目標訪談、提出者審問、保留清單。
- **不包含：** 下方 Not Doing 列出的所有項目。

## 實作步驟

1. 撰寫 `SKILL.md` 和目標訪談。驗證：`quick_validate.py` 通過。
2. 以符號連結安裝到 `~/.claude/skills/` 和 `~/.agents/skills/`。驗證：兩個平台都能列出並觸發 skill。
3. 在一個曾經人工瘦身的專案上，以瘦身前的提交做回歸測試，只產出提案，並使用獨立 clone。驗證：保護規則被保留，提案與實際刪除結果可比對。
4. 在過去專案的獨立 clone 中實測瘦身。驗證：三項成功標準。
5. 測試規劃審視，涵蓋檔案中的計畫、只在對話中的計畫，以及 Claude Code 的 plan mode。驗證：超出要求的項目被移除，必要步驟沒有被移除。
6. 測試通過後，加入兩個平台的 plugin manifest，再公開發布。驗證：從本機 clone 以兩個平台的安裝指令實際安裝成功。

skill 必須在主對話中執行，不設定 `context: fork`，否則讀不到對話中的計畫。

## Not Doing (and Why)

- **盤點腳本和實測移除：** 目前沒有證據顯示需要。
- **審查程式碼內部：** 超出已確認的範圍。
- **數字預算和追蹤檔案：** 原始 skill 的預算表從未填寫，主要文件量仍然下降。
- **多個 skill：** 目前沒有觸發條件成立。
- **`agents/openai.yaml`：** Codex 只把它列為選用檔案，沒有需要時不加入。

## Open Questions

- 單批次提案的執行成本是否可接受？步驟 3 的 Claude Code 測試每批約 2.3 到 3.2 美元、7 到 8 分鐘。
