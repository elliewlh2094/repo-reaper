# Goal interview

Use this when the user cannot state the project's core goal. The result is one sentence that every keep-or-delete decision depends on, so it must come from the user.

## How to ask

Ask one question at a time and attach your best guess with the reason behind it. People react to a wrong guess faster than they produce an answer from nothing, and a list of questions gets skimmed. Draw the guess from the README and recent commits.

Use the next question only if the last answer did not settle the goal:

1. Who uses this project, and what do they get from it?
2. If this project disappeared tomorrow, what would stop working, and who would notice?
3. What would make you call this project finished?
4. What does this project deliberately not do?

Answers such as "scalable", "clean", or "best practice" are not goals. Ask what the user would want if they did not have to justify it to anyone.

## How to finish

Restate the goal in one sentence, using the user's words:

> This project exists so that <who> can <outcome>.

Ask for an explicit yes. "Sounds good" and "whatever you think" are not confirmation, so offer two concrete versions and ask the user to choose.

If four questions do not produce a goal, stop and report that the items cannot be judged. Do not fall back to "it looks used" as the test.
